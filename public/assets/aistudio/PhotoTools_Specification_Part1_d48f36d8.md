## 1. システム概要および目的

本システムは、イベント・個人撮影（個撮）・併せ撮影等で撮影した写真フォルダ（RAW/取込データおよび現像後JPEGデータ）に対し、エクスプローラーの右クリックメニューから「被写体プロパティ」GUIを起動し、撮影メタデータおよびモデル（被写体・参加者）情報を一括登録・同期・台帳化するローカル業務ツール群である。

### 1.1 中核機能一覧
1. **ペアフォルダ自動解決と双方向メタデータ同期**：`取込` フォルダ側・`現像後` フォルダ側のどちらから起動しても、対応するペアフォルダを自動特定し、更新日時が新しい方の `写真情報.txt` を基準に双方を自動同期する。
2. **複数人登録（登録枠）と衣装・キャラ名個別管理**：1つの撮影フォルダに複数の被写体・参加者を登録でき、撮影区分・モデル名・Xアカウント・**衣装名ORキャラ名**を登録枠ごとに個別保持する。
3. **同日・同モデルからの衣装／キャラ名自動補完**：同一撮影日（親日付フォルダ配下の別フォルダ、または同フォルダ内の別枠）に同じモデル名の登録が既に存在する場合、未入力の「衣装名ORキャラ名」を自動検索して補完する。
4. **X（旧Twitter）表示名の4段階フォールバック取得と履歴検索**：アカウントID・URL入力から表示名をログイン不要で自動取得し、ローカルJSON履歴へ学習保存する。履歴ダイアログでは「同日のみ絞り込み」と「全件表示」を切り替えられる。
5. **MEGAクラウド共有URL自動取得連携**：現像後フォルダに対応するMEGA上の共有リンク自動検索・クリップボード連携を行う。
6. **Excel管理台帳（`写真管理一覧.xlsx`）自動更新**：保存実行時に、登録された全人数分（1人＝1行）のレコードをExcel管理台帳へ追記・上書き更新する。
7. **外部ツール（ギガファイル便自動アップロードツール）連携**：現像後フォルダのパスを引き渡してギガファイル便アップロードツールを起動する。

## 2. ディレクトリ構成およびファイル配置仕様

### 2.1 プログラム本体ディレクトリ（`D:\PhotoTools\`）

```text
D:\PhotoTools\
├── settings.ini                    # システム全体設定ファイル（パス・列定義・既定値）
├── MakePhotoInfo.bat               # エクスプローラー右クリックメニュー起動エントリ（Shift-JIS）
├── x_history.json                  # Xアカウント・表示名・撮影日 学習履歴（UTF-8 BOM）
├── scene_history.json              # 撮影シーン・区分・衣装/キャラ 学習履歴（UTF-8 BOM）
├── editor\
│   └── PhotoInfoEditor.ps1         # メインGUI画面・イベント制御スクリプト（UTF-8 BOM）
├── common\
│   ├── PhotoEditorLogic.ps1        # データ読込・同期・自動補完・台帳出力ロジック（UTF-8 BOM）
│   ├── XHelper.ps1                 # X表示名取得API通信・履歴検索ダイアログ（UTF-8 BOM）
│   ├── ExcelHelper.ps1             # Excel管理台帳（COM / OpenXML）読み書き制御（UTF-8 BOM）
│   ├── MegaHelper.ps1              # MEGA CLI / 共有リンク検索・生成ヘルパー（UTF-8 BOM）
│   ├── SceneHelper.ps1             # シーン名・event.txt/scene.txt 解析および履歴管理（UTF-8 BOM）
│   └── GigaFileHelper.ps1          # ギガファイル便アップロードツール連携ランチャー（UTF-8 BOM）
└── tools\                          # 保守・一括移行・アーカイブ整理用補助スクリプト群
```

### 2.2 写真データフォルダ階層構造（ストレージ側）

撮影データは日付単位の親フォルダ配下に、シーン名（イベント名・スタジオ名・キャラ名等）フォルダを持つ構造を標準とする。

```text
<取込ルート> (例: F:\写真\取込\ または G:\写真\取込\)
└── YYYY_MM_DD\                     # 撮影日フォルダ（例: 2026_11_21）
    ├── scene.txt                   # 同日共通シーン名メモ（旧 event.txt からも自動引き継ぎ）
    └── <シーン・フォルダ名>\        # 個別撮影フォルダ（例: コミケ107_1日目 / スタジオA）
        ├── 写真情報.txt             # メタデータ本体（UTF-8 BOM, CRLF）
        └── *.ARW / *.CR3 / *.JPG   # 撮影データ

<現像後ルート> (例: G:\写真\現像後\)
└── YYYY_MM_DD\                     # 同一日付フォルダ（例: 2026_11_21）
    └── <シーン・フォルダ名>\        # 同一シーン・フォルダ名（ペア対象）
        ├── 写真情報.txt             # 取込側と双方向同期されるメタデータ本体
        └── *.jpg                   # 現像済み出力画像
```

## 3. 技術的制約・文字コード・実行環境規定

### 3.1 文字コードおよび改行コード規定（厳守）
* **PowerShellスクリプト（`.ps1`）・設定（`.ini`）・JSON（`.json`）・`写真情報.txt`**：
  * **文字コード**: **UTF-8（BOM付き / `EF BB BF`）**
  * **改行コード**: **CRLF（`\r\n`）**
  * *理由*: Windows PowerShell 5.1 は BOM なし UTF-8 の `.ps1` ファイルを Shift-JIS として誤認識し、日本語文字列リテラルや全角記号（`【` `】` `（` `）`）で構文エラー・文字化けを起こすため。
* **Windowsバッチファイル（`.bat`）**：
  * **文字コード**: **Shift-JIS（CP932）**
  * **改行コード**: **CRLF（`\r\n`）**

### 3.2 PowerShell 実行ポリシーとインターネットブロック解除
* 外部環境からダウンロード・コピーした `.ps1` ファイルには NTFS 代替データストリーム `Zone.Identifier` が付与され、`RemoteSigned` 環境下でドットソース読込（`. .\common\XHelper.ps1`）時に `PSSecurityException: UnauthorizedAccess` となる。
* 起動バッチ `MakePhotoInfo.bat` は `-NoProfile -ExecutionPolicy Bypass -STA` で実行し、導入・更新時には必ず以下を実行する：
  ```powershell
  Get-ChildItem -Path "D:\PhotoTools" -Recurse -File | Unblock-File
  ```
* **スコープ規定**: UIスクリプト（`PhotoInfoEditor.ps1`）のトップレベルスクリプトスコープにて `common\*.ps1` を直接ドットソース読込（`. $path`）すること。関数内部でドットソース読込を行うとローカルスコープに閉じ込められ、WinForms イベントハンドラからヘルパー関数が参照不能になる。

## 4. 起動・ペアフォルダ解決・初期同期アルゴリズム

### 4.1 起動パラメータ仕様（`MakePhotoInfo.bat` ➔ `PhotoInfoEditor.ps1`）
* エクスプローラーのフォルダ背景右クリック、またはフォルダアイコン右クリックから `"%1"` として対象パスを受け取る。
* ファイルを右クリックして起動された場合は、親ディレクトリパスを自動抽出して対象フォルダとする。

### 4.2 ペアフォルダ解決ロジック（`Resolve-PairedPhotoFolders`）
1. 入力パスが `settings.ini` で定義された `RawRoot`（取込ルート）配下か、`DevelopedRoot`（現像後ルート）配下かを判定する。
2. ルート以下の相対パス（例：`2026_11_21\スタジオ撮影`）を抽出し、もう一方のルートパスと結合してペアフォルダパスを生成する。
   * 例：`F:\写真\取込\2026_11_21\スタジオ撮影` ⇔ `G:\写真\現像後\2026_11_21\スタジオ撮影`
3. どちらのフォルダから起動した場合でも、内部的には以下の3つのパスを保持する：
   * `$RawFolder`: 取込側フォルダパス（存在有無フラグ付き）
   * `$DevFolder`: 現像後側フォルダパス（存在有無フラグ付き）
   * `$PrimaryFolder`: 起動元フォルダパス

### 4.3 `写真情報.txt` 双方向最新同期（`Sync-PhotoInfoFiles`）
起動直後および保存直後に以下の同期ルールを適用する：
1. `$RawFolder\写真情報.txt` と `$DevFolder\写真情報.txt` の存在および `LastWriteTime`（最終更新日時）を比較する。
2. 片方にのみ存在する場合：存在する側のファイルをもう片方へコピーする（※相手側フォルダが存在する場合）。
3. 両方に存在する場合：`LastWriteTime` が新しい方のファイルを正本（最新）とみなし、古い方へ上書きコピーする。
4. 両方に存在しない場合：新規作成モードとして初期化し、フォルダ名から撮影日（`YYYY_MM_DD`）およびシーン名（`scene.txt` / 旧 `event.txt` / フォルダ名）を自動推定して初期値にセットする。

## 6. コア業務ロジック詳細仕様

### 6.1 撮影区分連動仕様
* `cmbCategory` の選択値に応じて、中段グループボックス内の衣装欄ラベルを動的に切り替える：
  * `イベント` / `個撮` / `併せ` 選択時：ラベルを **`衣装名ORキャラ名：`** に設定。
  * `その他` 選択時：ラベルを **`衣装：`** に設定（ポートレート・私服・作品撮り等の用途を想定）。

### 6.2 同日・同モデル選択時の「衣装名ORキャラ名」自動補完ロジック（`Find-SameDayCostumeForModel`）
* **発動トリガー**：
  1. `txtModelName`（名前欄）のドロップダウン選択確定時、またはフォーカス離脱（`Leave`）時。
  2. `btnFetchX`（X名前取得）による名前確定直後。
  3. `btnHistoryX`（X履歴検索ダイアログ）からの選択反映直後。
* **実行条件（保護ルール）**：
  * 現在選択中の登録枠における `txtCostume.Text` が**空欄（空白のみ含む）である場合のみ**自動補完を実行する。既にユーザーが文字を入力している場合は上書きしない。
* **検索優先順位**：
  1. **現在編集中の同一フォルダ内の他枠**：複数人登録時、別枠に同名が入力されていればその衣装・キャラ名を参照。
  2. **同一撮影日（`YYYY_MM_DD`）配下の他シーンフォルダ**：`RawRoot\YYYY_MM_DD\*\写真情報.txt` および `DevRoot\YYYY_MM_DD\*\写真情報.txt` を走査し、一致するモデル名に紐づく非空の `【衣装・キャラ】` 値を取得して自動入力する。

### 6.3 X（旧Twitter）表示名取得・クリーニング仕様（`XHelper.ps1`）
* **アカウント正規化（`Normalize-XAccount`）**：
  * `https://x.com/username?s=20`、`https://twitter.com/username`、`username`、`＠username` のいずれの入力も `@username` 形式に統一する。
* **表示名4段階フォールバック取得（`Get-XDisplayName`）**：
  * Xのログイン制限（Auth Wall）を回避するため、以下の順で取得を試行し、最初に有効な表示名が得られた時点で確定する：
    1. **X公式 oEmbed API**: `https://publish.twitter.com/oembed?url=https://x.com/<id>` の JSON 応答から `author_name` を取得。
    2. **fxtwitter 公開API**: `https://api.fxtwitter.com/<id>` の JSON 応答から `user.name` を取得。
    3. **vxtwitter 公開API**: `https://api.vxtwitter.com/<id>` の JSON 応答から `user_name` を取得。
    4. **HTMLメタタグ直接解析**: `https://x.com/<id>` の `og:title` または `<title>` タグから抽出。
* **表示名クリーニング（`Clean-XDisplayName`）**：
  * HTMLエンティティをデコードし、末尾に付与される `(@username) / X`、`/ X`、`on X`、および表示名中に含まれる `@肩書き・イベント告知`（最初の半角 `@` または全角 `＠` 以降）を自動除去して純粋なモデル名のみを抽出する。

### 6.4 Xアカウント履歴検索ダイアログ仕様（`Show-XHistoryDialog`）
* **ウィンドウサイズ**: `580px × 440px`（モーダルダイアログ `CenterParent`）
* **フィルタ機能**:
  * **リアルタイムキーワード検索**：名前または `@アカウント` に対する大文字小文字不問の部分一致フィルタ。
  * **「同日のみ (YYYY_MM_DD)」チェックボックス**：ON にすると、現在編集中の撮影日と一致する履歴レコードのみに絞り込む（OFF で全履歴表示）。
* **選択動作**：行のダブルクリックまたは「選択して反映」ボタンで呼び出し元へ `@{ account = "@..."; name = "..." }` を返却し、現在枠のアカウント・名前欄へセットしたうえで同日衣装自動補完を実行する。
